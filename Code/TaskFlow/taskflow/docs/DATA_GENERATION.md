# 06 — Data Generation

Six datasets. The rules below exist so that every number in `07_EVAL_METHODOLOGY.md`
means something.

| Dataset | Rows | Generated by | Purpose |
|---|---|---|---|
| `knowledge_base/*.md` | 42 docs | Claude (`kb-writer` subagent) | retrieval and citation source |
| `classifier_train.jsonl` | ~200/intent | **Ollama**, prompt A, personas A | fit the classifier |
| `classifier_validation.jsonl` | 15% stratified split of train | — | pick C, pick the abstain threshold |
| `classifier_test.jsonl` | ~40/intent | **Claude**, prompt B, personas B | honest in-distribution test |
| `golden_eval.jsonl` | 60–80 | **you, by hand** | the number that goes on the slide |
| `demo_scenarios.jsonl` | 5 | you | the demo |

## Why two different generators

Splitting rows is not enough. If train and test come from the same model with the same
prompt, "held out" only protects against memorisation, not against distribution collapse:
LLM-generated intent data is stylistically narrow, and a logistic head will score in the
mid-90s on its sibling data and fall over on real phrasing.

So: **train with Ollama, test with Claude, different prompts, different persona sets** —
and hold a hand-written golden set that no generator ever saw. Costs nothing extra, since
both providers are already wired.

## Knowledge base document schema

```yaml
---
title: "Refund Policy"
doc_type: policy          # policy | howto | faq | troubleshooting | pricing
product_tier: all         # free | pro | enterprise | all
intents: [refund, billing]
version: "1.0"
updated_at: 2026-07-01
---
```

`doc_id = sha256(relpath + "\n" + title)[:16]` — deterministic, so re-ingesting is
idempotent and chunk ids are stable across runs.

## Intentionally absent topics

**Do not write knowledge-base documents for these.** The sufficiency check and the gap
analyzer need genuine gaps, and scenario coverage that never fires is fake coverage.

- SAML / SSO configuration
- Data residency and regional hosting
- On-premises deployment
- Custom SLA terms for Enterprise

A question about any of these must produce `reason_code=retrieval_gap` and escalate.

## Leakage control

`scripts/check_leakage.py` runs across **every pair** of splits and exits non-zero on:

1. exact duplicates after normalisation (lowercase, strip punctuation, collapse whitespace)
2. near duplicates — embedding cosine similarity above 0.95

Run it before any metric is trusted, and after every dataset regeneration.

> **Verify your oracle.** Paste one training row into the test file and confirm the
> script fails. A leakage check that has never fired has not been tested.

## Manifests

Every dataset gets `data/manifests/{name}.json`:

```json
{
  "name": "classifier_train",
  "version": "1.0.0",
  "rows": 1400,
  "sha256": "9f2c...",
  "generator": {"provider": "ollama", "model": "qwen2.5:7b-instruct", "prompt_sha": "a13f..."},
  "created_at": "2026-08-20T10:04:11Z",
  "notes": "personas A; test set uses provider=claude with prompt B"
}
```

The classifier artifact records the manifest sha of the data it was trained on. That is
how you answer "which data produced this model?" six weeks later.

## Writing the golden set by hand

Sixty to eighty rows, written or heavily edited by you, adjudicated by you. Include:

- at least 5 per intent, including complaint and refund
- 8–10 deliberately ambiguous messages that *should* abstain
- 5 questions about the intentionally-absent topics (expect `retrieval_gap`)
- messages with typos, all-lowercase, no punctuation, and mid-thought openings
- `expected_intent` for every row, and `expected_doc_ids` where retrieval is relevant

This is a couple of hours of work and it is the single highest-value data in the project.
